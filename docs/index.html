One core, explicit boundaries

The document stays on the CPU.
The bounded work can travel.

Recursive JSON trees, context inheritance, dynamic maps, and document loading remain in the native Swift core. Dense, bounded byte and integer workloads have versioned contracts in CBORLDCompute, so any backend can take them on and be checked against the CPU reference. A commercially licensed SemanticCompute adapter is planned as a separate package.

01

Context aware

Remote, embedded, imported, type-scoped, and property-scoped contexts with protected-term and propagation behavior, loaded only from sources you supply and bounded per operation.

02

Untrusted-input limits

Presets and explicit bounds for input bytes, nesting depth, container sizes, duplicate keys, indefinite lengths, preferred widths, and encoded output size.

03

Prepared sessions

Build dictionary indexes once, share a bounded context cache, stream batch results, and preserve per-document semantic isolation across concurrent work.

04

Inspectable integrity

Transport hashes, structural fingerprints, pinned resources, verification reports, and versioned out-of-band manifests.

Commercial acceleration boundary

The planned adapter will require the SemanticCompute binary package and a SemanticCompute licence; Swift‑CBORLD 0.1.0 neither includes nor needs it. Its CPU fallback will preserve results when a dispatch is unsuitable, but will not remove the build, link, or redistribution requirement once the adapter is imported.

dependencies: [
  .package(
    url: "https://github.com/entertrainmentuk/swift-cborld.git",
    from: "0.1.0"
  )
]
import CBORLD

let bytes = try await CBORLD.encode(document)
let restored = try await CBORLD.decode(bytes)

precondition(restored == document)
